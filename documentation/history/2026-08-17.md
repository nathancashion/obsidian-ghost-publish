# 2026-08-17

## Footnotes broken on published posts — Littlefoot popovers dead (fixed)

User report: a post created manually in Ghost via a Markdown card gets working
Littlefoot footnote popovers; the same content published through this plugin
does not.

### Diagnosis

Compared the stored lexical of both posts in a local Ghost instance
(`posts.lexical` in the DB):

- **Markdown card post**: stored as a `markdown` card, rendered server-side at
  page build → proper `<sup class="footnote-ref">` refs and `<li id="fnN">`
  targets.
- **Plugin post** (`source=html`): Ghost's `kg-html-to-lexical` importer
  flattened the footnote refs into `link` nodes (superscript text format — this
  part survives as `<a href="#fn-1"><sup>1</sup></a>`) but converted the
  `<section class="footnotes">` into a plain lexical `list`. **Lexical list
  items cannot carry `id` attributes**, so every `#fn-N` target vanished.
  Littlefoot finds no footnote bodies → no buttons, and plain anchor
  navigation is broken too.

### Fix

`services/footnotes.ts`: wrap the emitted footnotes section in
`<!--kg-card-begin: html-->` / `<!--kg-card-end: html-->`. The importer stores
that region verbatim as an html card, preserving the `<li id="fn-N">` targets.
New rule **BR-PROC-6** documents this.

Known trade-off: inline `id="fnref-N"` back-targets are still stripped by the
importer (lexical text/link nodes can't carry ids), so the ↩ backref links
don't scroll without JS. Littlefoot is unaffected — it matches refs by href
pattern (`/(fn|footnote|note)[:\-_\d]/`) and positions popovers at the ref.

### Verification

- Unit: new spec asserts the kg-card markers wrap exactly the footnotes
  section. 117 tests pass; tsc/lint/build clean.
- End-to-end (no Obsidian needed): ran the real test-note markdown through
  `parseMarkdownWithFootnotes`, then through the Ghost container's own
  `@tryghost/kg-html-to-lexical` → `@tryghost/kg-lexical-html-renderer`
  (`docker exec`, same libs Ghost runs). Result: `paragraph, paragraph, html`
  top-level nodes; every `href="#fn-N"` ref resolves to an existing
  `id="fn-N"` target.
- Deployed `dist/{main.js,manifest.json,styles.css}` to the user's vault
  (`Vault/.obsidian/plugins/ghost-publish/`). **Manual runtime check still
  needed**: reload Obsidian, force a re-sync of the test note (edit body or
  drop the `contentHash` frontmatter — BR-SYNC-1 short-circuits unchanged
