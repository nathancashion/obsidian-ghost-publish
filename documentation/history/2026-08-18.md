# 2026-08-18

## First real citation post — three fixes from user feedback

User published "Low back pain shortens years of life" with a bare
`@citekey`, a `[@citekey]` in a blockquote, and an inline `^[aside]`.
The aside worked; both citations published as literal text.

### Root cause (single): pandoc never ran on the note

Diagnosis against the local Ghost DB + vault frontmatter: the post
content was pushed at 20:52 (citations toggle not yet enabled), the user
enabled the toggle and re-synced at 20:55 — which **short-circuited to
`unchanged`** because the content hash covered only the note body.
Verified `hasCitations` returned true on the note and the vault build /
settings / toggle were all correct. Neither the bare key nor the
blockquote was a rendering bug: the full chain (pandoc → footnotes →
lexical) handles both, verified end-to-end (blockquote renders as
`<blockquote>…<a href="#fn-N"><sup>N</sup></a></blockquote>` with the
target intact).

### Fixes

1. **Bare citekeys now trigger + render** (user request — they use bare
   `@key` frequently). `hasCitations` matches `@key` not preceded by a
   word char (emails immune). `@handle` mentions in citations-enabled
   notes must be escaped `\@handle`; the escaped form still triggers the
   pandoc run (pandoc strips the escape). BR-PROC-7 updated.
2. **Citation config folded into the content hash** (`citationConfigFingerprint`)
   so toggling citations / changing paths invalidates `unchanged`.
   Empty fingerprint when citations off → non-citation presets keep
   their hashes. BR-SYNC-1 updated. Known limit: `.bib` content edits
   don't invalidate.
3. **pandoc binary resolution** (`resolvePandocBinary`): macOS GUI apps
   run with the minimal launchd PATH (no `/opt/homebrew/bin`), so
   `execFile('pandoc')` would ENOENT from Obsidian even with pandoc
   installed. Bare commands now resolve against PATH + Homebrew/local
   bins. Not yet user-reported (masked by fix 2's bug) but would have
   been the very next failure. Also: non-fatal citeproc stderr now
   logged as warnings.

137 tests pass; tsc/lint/build clean. Deployed to vault.

Gotcha for the ages: an Edit introduced a literal NUL byte into
sync-note.ts (template separator), making grep treat the file as binary.
tsc still compiled it. Removed; separator is a plain space.
