# 2026-08-22

## Image captions + markdown-image uploads

Reported from a live post (`/ordinal-decades-and-axis-anchoring/`): two of four
images published, two leaked as literal `![[…]]` text.

**Root cause.** `upload-vault-images.ts` matched embeds with
`/!\[\[([^\]]+?)\]\]/g`. `[^\]]` cannot cross a `]`, and the two failing
captions contained markdown links — `[O'Bryan et al., 2025](…)`. The embed
never matched, passed through untouched, and `marked` then rendered the inner
link, producing a real anchor inside literal `![[…]]` text on the published
page. The two plain-text captions matched fine, which is why the failure looked
syntax-related rather than caption-content-related.

Regex is now `(?:[^\]]|\](?!\]))+?` — tolerates single `]`, stops at `]]`. The
alias is split on the **first** `|` only (`indexOf`, not `split`), so captions
may contain `|`; the old destructure silently truncated them.

**Captions were never captions.** The old code emitted `![alt](url)`, so the
alias landed in the `alt` attribute and rendered nowhere. Captioned images now
emit `<figure class="kg-card kg-image-card kg-card-hascaption"><img><figcaption>`
— the shape Ghost's own renderer produces.

Verified through `@tryghost/kg-html-to-lexical@1.4.0`: imports back as a
**native** `image` node with `caption` populated and the caption's link HTML
intact — not an html card, so it stays editable in Ghost Admin. Confirmed for
both the emitted single-line form and pandoc's reflowed multi-line form (pandoc
round-trips the block verbatim; checked with the same reader/writer extension
set the citation path uses).

**Standard markdown images now upload too.** Previously only `![[…]]` was ever
resolved against the vault, so `![alt](chart.png)` shipped a bare filename that
404'd on Ghost. Now both syntaxes resolve; targets are `<…>`-unwrapped and
percent-decoded first. `alt` stays alt and the optional markdown **title**
becomes the caption — the closest thing to a standard caption convention, and
it keeps alt semantically correct.

Design points:

- Caption markdown → inline HTML via `marked.parseInline`. `<figcaption>`
  content is inline inside a raw HTML block, so neither pandoc nor `marked`
  parses it downstream; it has to be converted at emit time. Author-written
  inline HTML passes through.
- Block/inline split: a `<figure>` mid-paragraph would split the paragraph, so
  `occupiesOwnLine` gates it. Inline captioned images degrade to `![alt](url)`
  with the caption flattened to alt text.
- A bare-size alias (`300`, `640x480`) stays a size hint, matching vanilla
  Obsidian, rather than becoming a caption.
- Unresolvable **markdown** images are left in place (deleting an author's
  markup on a typo is worse than a broken image); unresolvable **embeds** are
  still dropped, unchanged from before.

Pure helpers extracted to `utils/image-embeds.fn.ts`; `upload-vault-images.ts`
keeps only the I/O. BR-PROC-4 rewritten, BR-PROC-11 added. 201 tests pass
(37 new across the two spec files), lint and tsc clean, build succeeds.

## Forest theme: figure and bold styling

After the captions shipped and rendered correctly, Nathan asked for three
adjustments. All three override `@tryghost/shared-theme-assets` (vendor, in
`node_modules`, never edited) from the theme's own `assets/css/screen.css`,
which is imported after it:

- `figcaption` 1.4rem → **1.6rem** (root font-size is 62.5%, so 16px). The
  shared default read small against this theme's 2rem body text.
- Images and captions **left-aligned**: shared assets set
  `.kg-image { margin-inline: auto }` and `figcaption { text-align: center }`.
  Overrides scoped to `.gh-content` so feed and feature imagery keep their own
  layout.
- `strong`/`b` → **600**. There was no weight rule anywhere in the stack, so
  bold fell through to the browser default 700, which GeneralSans-Variable
  renders heavily. One `.gh-content` rule covers blockquotes and callouts too.

Specificity checked rather than assumed: each override is one class heavier
than the vendor rule it beats, so order-independence holds. Ghost core's
`/public/cards.min.css` (which loads *after* the theme CSS) has no `figcaption`
rules, so nothing downstream reclaims them.

Verified end-to-end: `npx gulp build`, `docker restart ghost-ghost-1`, asset
hash moved `a80b1e39b5` → `bfbfef48c5`, and all three rules confirmed present
in the CSS served from the new hashed URL.
